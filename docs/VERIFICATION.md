The final pytest run used `.venv-clean`, created afresh from `requirements.txt`; the complete
resolved set is recorded in `requirements.lock` and was reinstalled successfully. Python
3.12.14, PyMuPDF 1.26.7, SQLite via Python, and Tesseract 5.5.0 were used on Linux. The
initial PyMuPDF 2.0 installation included an expanded layout/ML dependency tree; the project
was deliberately pinned to 1.26.7 and checked again in the clean environment. No TLS or
checksum verification was disabled.

The synthetic demo ran against real FastAPI routes with a fresh isolated database. Its
battery and inflation tests changed from current to stale after v2. The emergency-venting
source stayed current. Both versions remained browsable; the exact selected v1 nodes and
original generated JSON stayed unchanged. The E3 table regression separately verifies
2-second to 1.5-second changes and E6's addition. The original PDFs may have different
layouts; synthetic success is not a substitute for their inspection.
